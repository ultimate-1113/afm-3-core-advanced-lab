# 表編集の誤適用を減らす追試

前回の12問は回帰用に使う。追加の32問は未測定の合成表とし、Core Advancedでの初回生成前に入力・正解・採点器・方式・指示を固定する。24問は値の増減、絶対値の設定、条件付き設定を各6問。4問に言い換えを用いる。8問は対象が重複、未指定、数量が未決、複数対象、または非負整数の範囲外で、人の確認を求めるのが期待される。元の依頼を解釈しきれず保留した有効な依頼は未完了として数える。

| 方式 | 何をするか |
|---|---|
| 前回の差分＋再読（baseline） | 表の全文をモデルに見せ、区画・旧行・新行を提案させる。版変更時は1回再読。旧行が指定区画内で一意なら差分を適用する。 |
| 対象を検査（scope） | 同じ提案を再利用し、依頼全文を解釈できた場合に対象区画・キー・旧行・件数・数値欄の形を照合する。 |
| 対象と値を検査（checked） | 同じ提案に対し、現在値で前提条件を評価。求められる新しい値、または正当な無操作と一致する場合だけ更新する。余分な行を含む提案は全体を保留する。 |
| 1行だけで提案＋検査（scoped） | 確認できた対象行と依頼文をAFMに渡し、更新後の数値だけを提案させる。対象の決定、条件判定、適用時の値の照合はコードが担当する。条件不成立や同値はコードで無操作と確定し、解釈できない依頼は保留する。 |
| 通常コード（rules） | 同じ解釈器・適用時の検査で、確定した演算を直接行う。モデル呼び出し0回。 |

モデルに送るのは合成の依頼と観測時点の表または該当行のみ。正解・最終状態・算出した正しい新値を生成入力に含めない。過去12問の基準回答は保存済みのものを使い、元のSHA-256とモデル経路を照合する。新規32問の全文方式には、単一の非負整数セルに限定し、不明・複数対象・範囲外なら空配列にする共通の業務条件を加える。従来の差分形式では空配列が、要確認と確定した無操作の両方を表し得る。新規生成はOS付属のfm、モデルsystem、greedy、新規セッション、並列度1。PCCは11月24日分の利用枠に到達している。

完了には正しい更新と、確認済みの正当な無操作を含める。正解が無操作でも、単に保留したものを正解に繰り上げない。意図に合わない完了を誤受理とし、うち実際に行を書き換えた誤適用、対象外変更、消えた他者の更新を別に数える。要確認8問では、保留・無変更で完了扱い・誤書き込みを別集計する。方式ごとに正答からの転落、追加で完了した件数、呼び出し回数、前後処理とCLIを合わせた中央値も示す。

共有するメモリ上の表には単調増加する版番号を持たせる。読み取りとモデル生成の間はロックを持たず、適用直前の版確認と書き込みだけを同じロック内で行う。版が変われば1度だけ再読し、再競合なら保留。完了した要求IDは同じ表の生存期間中に記憶して二重加算を防ぐ。版が変わって値だけ元に戻る更新や同一要求の同時到着は別の回帰試験で確認する。考え方の参照先はJSON PatchのtestとHTTPのIf-Matchである。[値の前提条件](https://www.rfc-editor.org/rfc/rfc6902.html#section-4.6)・[版の前提条件](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1.1)
