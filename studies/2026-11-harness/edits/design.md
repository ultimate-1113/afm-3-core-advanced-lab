# 差分適用と読み直しの追加試験

Codexの差分適用器は文脈と置換前の行を探索し、期待した行が見つからない場合にエラーを返す。DeepSeek Harnessのファイル編集ツールは、オプションの観測ポリシーを有効にすると、読み取った版が変わった際の書き込みを拒否する。標準構成ではこのポリシーは無効である。本試験はこの2つの考え方を、小さな管理表の独自実装で検証する。上流のコード・プロンプト・CLIを組み込んでいない。[Codexの行探索](https://github.com/openai/codex/blob/a0d5b0a661db3b34cd87bdf1c93736b90fd3694b/codex-rs/apply-patch/src/file_update.rs)・[DeepSeekのファイルツール](https://github.com/deepseek-ai/deepseek-harness/blob/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/fs/tool-fs/README.md)

日本語の表12問には、同名のキーが異なる3区画にある。変更なし、別区画への同時変更、対象行への同時変更、その両方の4条件を各3問用意した。3種類の依頼は相対加算、絶対値の設定、条件付き変更。初回の入力には読取時点の表のみを渡す。同時変更は生成と適用の間にメモリ上で再現する。読み直し可能な方式だけが2回目に現在の表を受け取る。正解と対象行の番号は採点時だけ参照する。

| 方式 | 初回の提案 | 競合した場合の処理 |
|---|---|---|
| plain | JSON指定の文章だけで全文を返す | そのまま全文を適用 |
| full | 同じ全文生成に型を指定 | そのまま全文を適用 |
| patch | 区画・旧行・新行を型付きで返す | 現在の区画の旧行と一致するときだけ適用。複数変更は全件まとめて採否を決める |
| full_hold / patch_hold | full / patch と同じ初回回答 | 読取時点と現在の版が異なれば保留 |
| full_read / patch_read | full / patch と同じ初回回答 | 版が異なれば再読し、新しいセッションに現在の表と元依頼を渡して1回だけ提案し直す |
| rules_read | 現在の表を受け取り、この定型依頼を正規表現で解釈して更新する | AFMへの要求は0回 |

全条件で正しい更新が完了した件数、適用せず保留した件数、依頼外の行まで変更した件数、同時変更を消した件数を別々に数える。競合を検出して保留しても更新完了には数えない。条件を満たさず元の表を保つのが正解のケースでは、正当な無操作を完了に含める。読み直し後のモデル時間は初回と合算する。再読が許すのは1回で、その間の追加変更は発生しない設定。実際のファイルへの書き込み権限は使わない。
